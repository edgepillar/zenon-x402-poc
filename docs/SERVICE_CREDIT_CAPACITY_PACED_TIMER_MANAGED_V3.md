## Concrete implementation

The new controller composes the genuine pinned timer-parent source gate,
complete profile bundle, resource planner and outer-V4 validator. Its future
execute branch uses the actual task-storage API, a new unused private store,
retained complete profile/entry objects, independent TLS clones, one test-TLS
command and one Node-parent command. It does not initialize/adopt a store,
rewrite a historical helper, retry a payment/command or erase child-created
files. Unknown SQLite/pin descendants remain HOLD.

The separate standard-library command DATA module binds the complete parent
profile, all 551 public source-row declarations and the entire entry plan to
the exact eight Node arguments and nine environment selections. The actual
controller consumes that same plan for argv, environment, timeout and stdout;
it reuses the one decoded parent for source identity rechecks. It does not
reserialize a second whole parent profile or substitute a compact namespace.

Parent profile version 3, resource plan version 3, outer capture version 4 and
timer capture version 1 stay distinct. Original 543-row R4 children are
unchanged. Every resource/policy field is compared with exact types, including
bool/integer separation; a workload-only 32-field parser is not reused on the
larger resource output.

The controller retains the existing floor plus allocation, metadata and every
other store reservation. Its authored inventory adds before/after task-list,
full task-record identity and scratch-presence snapshots around the unchanged
reservation reader. It recognizes all managed sibling roots, not only a
chosen prefix or the old 32-root list. These snapshots are cooperative source
logic, not executed measurements or a cross-store OS lock. They cannot release
a reservation or bypass an unknown-file/link/mount refusal.

Storage receipt timestamps are parsed separately as finite metadata numbers;
source plans still reject floating-point declarations. This avoids falsely
treating a normal fractional completion timestamp as an integer source plan.
