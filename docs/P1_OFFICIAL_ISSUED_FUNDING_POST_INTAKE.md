## Source-confirmed resource incompatibility

Actual intake issues a canonical resource with only `url` and three funding
commitment `tags`. Existing pinned `@x402/core@2.23.0` HTTP source always adds
empty `description` and `mimeType` properties. The local resource comparator
distinguishes absent optional properties from present empty ones.

At the actual supported scheme enrichment hook, before the unchanged existing
tuple bridge captures its challenge, the binding checks the complete selected
requirement and original resource values. It forms only the SDK-owned unsigned
response's `resource` field from the retained issued resource. It retains the
same SDK response, context, accepts array, selected requirement identities and
transport. It never rewrites the signed payment header, payload or requirements.

The pinned normal upfront HTTP caller does **not** supply a payment payload to
this hook: the six-field context owns `paymentPayload: undefined`. The binding
requires that actual shape; it does not invent a payload for enrichment.
Original header/resource/requirement checks remain before intake and SDK entry.
The existing bridge already allows the larger SDK enrichment context and the
transport's extra route-pattern field. It is unchanged; no ABI repair is claimed.

The package JSON and two relevant installed source chunks were read-only pinned
without importing or executing the package. Version text alone is not runtime
compatibility proof. The result records their digests, not private install paths.

## Original operation, pending and closure

BOUND records verified signed-block intake, not publication acknowledgement,
chain inclusion, official settlement, grant activation or service delivery.
The source root returns independently named intake and official outcome domains.
It does not translate a settlement receipt into BOUND.

An exact original-header replay reads the retained result without another intake,
verifier, first settlement or funding send. A pending observation is a separate
explicit call on the same retained continuation. Foreign or changed originals
cannot select another context or refresh the quote.

Close fences admission, closes actual intake admission, requests continuation
close at most once, and joins active work under the existing cooperative drain
budget. It retains a late pending result long enough to close it. Unknown
observation or close remains HELD; there is no late upgrade, force-close,
replacement signature or reopen. Borrowed SQL stores are never closed by this
root. These source contracts still need actual current-graph qualification.
