## Real profile producer and bounded DATA work

`qualification/native_capacity_current_offered_parent_v2.py` captures the pinned, unmodified current
V4 child producer and its existing Python metadata dependencies. The DATA
factory validates the whole current child graph and seven parent extensions.
It detaches caller-owned tables, preserves full private profile bytes and
rejects incomplete pairs, changed contexts, redirected role URLs, duplicate
profile paths/digests, logical or physical root aliases and nonprivate roots.

The planner caches four canonical fields within a 1 MiB bound. In the actual
32-child DATA case, 405,895 shared canonical bytes were retained and the parent
profile was 222,835 bytes. All 32 complete child profiles were compared.
No large source table was serialized again during parent validation and no
second whole expected child profile was materialized. Source/package tree
copies were zero. These counts describe the Python DATA algorithm only:
native preloader performance, heap use, latency and sustainable capacity were
not measured, and are not inferred from these numbers.

The optional source-context CLI is not executed by this qualification.
It is distinct from both the synthetic registry factory and native admission.
Claimed identities in DATA inputs do not authenticate a filesystem root,
installed package tree, Node binary, child process or native run.

## Actual local verification

The new isolated Python 3.12.14 control ran once: **64 passed, zero failed,
zero errors, zero skipped**. It executed the actual Python producer and
pinned metadata helpers, not a smaller reimplementation of their semantics.
Cases include complete-byte agreement with the genuine V4 child producer;
all current overlays and parent additions; all 32 paired child profiles;
changed manifests, contexts, identities and full source rows; recomputed
digests; noncanonical child bytes; alias rejection and detached caller data.

Four Node 24.19.0 `--check` operations passed against the exact new native
files. Parser checks do not import those files or execute their dependencies.

The test audit observed zero subprocesses, sockets, SQLite opens, write
opens, outside-source reads or mutations. The outer DATA controller launched
one isolated Python test process; the four separate parser processes were not
application children. These cooperative controls do not provide an OS or
network sandbox guarantee. All 318 prior protected input identities/bytes and
all before/after control pins remained unchanged.

The 160 current application source files were checked against the selected
rows. The 404 package rows are retained source pins: their installed bytes
were not reread and SDK/x402/Noble packages were not imported. No SQLite,
TLS, key generation, signatures, nonce search or application child process
ran. No storage manager/root, task, reservation or historical file was changed.
Neither the existing one-clean native allowance nor the old R4 allowance
was consumed or widened.

Exact source pins, control names, exits and bounded output digests are in
[`native-capacity-current-offered-parent-v2.actual-local-result.json`](../qualification/native-capacity-current-offered-parent-v2.actual-local-result.json).

## Roadmap status and next gate

GO for continued source integration only. Current native P1/P2 behavior,
independent runtime/chain/provider/operator acceptance and P4 real-load,
error, latency, balance-pressure and sustainable-capacity acceptance remain
open. Parent and child clock domains are not declared aligned.

Next, bind the same full current graph to a complete resource plan, managed
launcher and outer receipt path, then qualify any separately admitted native
attempt against that exact graph. A current native run requires its own
finite authority and successful storage admission. Do not execute it under
the old clean/R4 scope, bypass a storage refusal, restore historical runtime
bytes or relabel source/DATA/parser results as native evidence.

This new native source family is development-only. Existing main CI is a
separate 27-control profile and does not qualify these sources. No workflow,
package profile, CI retry or manual dispatch is part of this increment.
