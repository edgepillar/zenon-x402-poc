## Actual namespace, not a replacement runtime

`issued-funding-post-native-vertical.preload.draft.mjs` checks every input byte
and physical identity before the case imports. Its eight closed bare edges
point at real existing Noble, SDK, official core and Zod files. All other
resolution delegates to native Node and must land in the pinned file/builtin
set. There is no source/format load hook or native-builtin alias.

The exact case mode is part of the private profile. One process selects either
`clean` or `lost-ack`, not both; a mismatched environment/profile is refused.
The actual store's fchmod is not replaced. The runtime has no Node Permission
Model here, and neither the loader nor file checks are an OS/network sandbox.

Private file URLs and physical identities remain in memory/private task data;
they are not copied into this public inventory or report. Version labels and a
successful read-only profile do not establish runtime import compatibility.

## Avoiding unnecessary source duplication

The actual graph contains 4,363,667 source bytes, larger than the old 4 MiB
namespace limit. It has not been truncated or replaced with an easier graph.
The new bounded read ceiling is 6 MiB. This is an existing-source read limit,
not permission to allocate a larger qualification task.

The authored launcher keeps existing SDK/application inputs read-only in place
and retains their complete pins. It preserves only the small control sources,
case/preloader and manifest, plus the private profile and actual receipts in a
future managed task. The current plan's control-source retention is 252,508
bytes; the private profile is 216,221 bytes. The task quota remains 4 MiB.
No existing packages or application tree are recopied as a second snapshot.
These are measured source/profile sizes and an authored retention plan, not
measured APFS reclaim or an executed native disk/performance benchmark.

## One reviewed case only

The new launcher defaults to source-only. A trusted Python runtime may perform
the non-native source check explicitly:

```text
python3 -B qualification/run-issued-funding-native-vertical.local.py \
  --repo ABSOLUTE_REPOSITORY_ROOT \
  --manifest-sha256 296dd3eee42e0756dc93e9b720f838ec2ff180a3ba898f4253bdae8d4d4a5b47 \
  --source-only
```

Read-only `--pre-native-plan` additionally needs explicit existing package,
manager, Node and mounted-storage selections. Neither command, the manifest,
the `--execute` flag nor a passing parser test grants native execution authority.

The proposed per-case ceiling requires separate approval: five new SQLite
paths, two independent original/pin files, four synthetic Ed25519
keys, one transaction signature, three capability signatures and two provider
envelopes. Test TLS material is separate. The source graph includes one actual
bounded producer window, a bounded independent reference and fixed verification
reservation within 65536 total candidates. It permits no SDK PREPARE, install,
external endpoint, real wallet/payment, live pilot or default-buyer cutover.
One process uses at most 182 loopback connections and zero Node children; 96
connections are an expected transcript count, not an observed result.

The managed launcher limits one fresh task to one OpenSSL and one Node command,
with explicit source/binary/package/mount/capacity rechecks before either. The
Node process has a cooperative 30-second case timeout and a 90-second manager
capture bound; these are not an OS execution/lifetime guarantee. Native capture
must contain the exact one-test TAP result, case counts and current namespace
seal. A zero exit, skipped case or synthetic parser transcript is not enough.

Actual task close, cleanup disposition and native selected-case status remain
separate. Child-created SQL/pin files are protected, not silently disposable.
The intentionally HELD V6 case is never force-closed, reopened or deleted.
