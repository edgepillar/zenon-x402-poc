# Funding BOUND response-loss selection

This package prepares the missing funding-response-loss part of the
[updated roadmap](ROADMAP_20261028.md). It records source, DATA/callback and
syntax checks; those checks do not execute or qualify the native application.
The selected application runtime files are identical to V5. Only four
qualification rows change, preserving 135 application and 404 existing package
inputs. Native candidate files belong to the development branch
`x402/p1-router-late-pending-close-integration-v2`; publishing this report on
main is not application runtime adoption. The new source inventory is 5,229 bytes smaller.

The actual intake commits BOUND before entering official verification and first
settlement. The new native fixture captures the exact admitted POST, Host and
original PAYMENT-SIGNATURE and arms one genuine response-socket stop. At the
selected first-settlement callback it reads the genuine existing intake row by
selection key, checks the original resource, funding commitment, transaction
hash, payload digest, intent digest and issued header, then requests one stop.
There is no substitute response/store, native prototype patch, polling loop or
second server. BOUND is not publication, inclusion, a grant or delivery proof.

[All 19 gate DATA/callback controls passed](../qualification/funding-bound-response-loss-gate.actual-local-result.json).
They cover wrong originals, an uncommitted/missing row, accessor/proxy inputs,
read and actuator failures, reentrancy, early callbacks and duplicate stops.
UNKNOWN is sticky and no callback grants execution or retry authority.

[The V6 source/decoder controls also passed](../qualification/sdk105-issued-command-application-v6.source.actual-local-result.json):
18 declared transcript/source cases and three JavaScript syntax checks. Synthetic
accepted decoder input is not an actual native success. The controller rejects
nonzero/incomplete receipts, duplicate completion, source/mode substitution,
second signing, any grant/execution, missing BOUND matching and cleared client
uncertainty. All existing application runtime rows remain unchanged.

The source-selected native case commits the independently pinned original,
loses the response after actual BOUND, requires client OUTCOME_UNKNOWN and
HELD/UNKNOWN ownership, and checks the service ledger remains unchanged with
zero grants/requests/executions. Reentering the owned session must return its
retained rejected run. It does not directly close/reopen HELD payer or borrowed
stores. It needs no capability key generation or capability/provider signature;
only one synthetic transaction key and the fixture's synthetic provider key are
constructed. The latter is not used to sign an attestation in this case.

The single mode is `funding-response-loss`; clean, pending, service-loss and P2
cannot inherit its selection. Native execution needs a separate concrete finite
scope and direct approval. The public source controller has no execute flag.
Existing V4 clean, V5 pending and the selected V5 service-loss evidence are kept
without rerunning them. The authorized 108-control CI profile is unchanged.

Backend wire replay, fresh-process same-file recovery, the complete late-close
matrix, physical resource release and economic/production acceptance remain
separate open gates. This package does not claim those outcomes.
