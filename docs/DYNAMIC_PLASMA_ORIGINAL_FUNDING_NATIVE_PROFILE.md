## Actual code, explicit namespace

The full existing SDK entry remains selected; it is not replaced with a smaller
model-only SDK, mock namespace, fake preflight or substitute store. Declared
package versions are SDK 1.0.5, Noble Ed25519 2.3.0 and Noble hashes 1.8.0. These
names/versions describe the selected local package bytes, not authenticated npm
release provenance or compatibility of every installation.

The application checkout has no ordinary installed node_modules namespace.
Copying the entire declared 2.5 MB input closure into qualification scratch
would exceed the existing 2 MiB task quota before streams and SQLite fixtures.
An ordinary npm/omit-dev installation therefore remains a SEPARATE unqualified
profile; there is no hidden install, source rewrite or home-cache fallback.

The preload uses Node 24.19.0's synchronous registerHooks API in the same process.
Exactly five application import edges, for three package specifiers, point to
the reviewed EXISTING real package files. Every other edge delegates unchanged
to Node's default resolver and must return a declared file or builtin. The
native result, module format and source loader are not replaced or transformed.
No asynchronous loader thread, worker or child is enabled. See the
[Node 24.19.0 module API](https://nodejs.org/download/release/v24.19.0/docs/api/module.html#moduleregisterhooksoptions).

Before the fixture imports, the preload checks every declared input's hash and
nine-field physical identity. Its exact fixture hash and three declared package
versions must match. Subsequent resolves recheck identities and reject
undeclared URLs. The profile file itself is separately SHA-256 pinned.

This is a cooperative source/namespace guard, not a hostile-code or same-user
sandbox. Native Node and dependency behavior remain premises. An environment
selection string is only an accidental-launch guard, NOT proof of human
authorization, source trust, payer consent or economic authority.

## Declaration versus actual execution

The candidate closure has 429 files and 2,537,526 bytes, including the preload.
It is derived from literal imports/requires plus the three selected dynamic
dependency imports in the actual preflight loader. It is a declared conservative
closure, not a count of files actually evaluated.

Review separates 44 JSDoc type references and an embedded browser-module string
from executable imports. The SDK's PoW initialization and key-file password
hashing paths contain deferred imports; this fixture does not call them.
Unrecognized runtime module resolution still refuses rather than silently
expanding the declaration. VM-based ASN.1 codec creation is not part of this
account-block/preflight path. No PoW initialization or nonce search is selected.

WS_NO_BUFFER_UTIL and WS_NO_UTF_8_VALIDATE explicitly disable optional websocket
native accelerators, while Node addons and string code generation remain
disabled. NODE_DISABLE_COMPILE_CACHE prevents compiler-cache writes. No RPC,
socket, wallet-file read, SDK prepareBlock, payment publication or chain PREPARE
is selected. The two tests use only synthetic read callbacks, a fixed
zero-difficulty nonce, one new in-memory synthetic key and two signatures.

The source profile's proposed read grants comprise 47 exact application files,
67 declared package-directory scopes, the pinned profile object and the new
owned scratch directory. Package-directory grants are broader than individual
file grants; they are NOT described as an exact-file filesystem sandbox. The
resolver's module allowlist and byte/identity checks are separate guards.
Write access is only the new owned scratch, with no child/worker/addon permission.
