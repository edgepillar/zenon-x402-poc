Construction captures a bounded finite plan and 1-16 distinct lane/profile

uniqueness alone is NOT proof of physical root/owner independence.

commit/POST, activation and handoff. Service commands preserve cohort/ordinal
and require the actual pair's successful store-backed result. No raw error,
private profile path, checkpoint, header or key is placed in the public result.
There is no retry, new original, re-signing or replacement on uncertainty.

## Fresh balances and real observation overhead

Every owner balance barrier calls the actual pair's readBalances() method,
which sends a new BALANCES command to the service child. The prior cached
pair inspection is never used as a read result. Expected units come from the
finite plan and independently accepted completed originals, not the returned
available/held/consumed fields. The strict BigInt DTO still grants no economic
or native-event authority.

The final tracked balance capability also retrieves actual service writer
timing pages before close. Pages are bounded to 64 entries, at most
ceil((12 * totalCalls + 64) / 64) pages, stable totals, contiguous ordinals and
complete local brackets. Unknown/active/missing traces withhold measurement.
Nominal balances use the real store's writer-style read transaction; that
observer cost is not hidden or called free.

Parent balance/read-and-page round-trip uses the parent's monotonic clock.
Payer operation records stay in PAYER_CHILD_LOCAL. Actual writer brackets stay
in SERVICE_CHILD_LOCAL and include JavaScript and identity checks. No child
clock is subtracted from a parent timestamp. No SQL time is inferred from a
funded-call Promise; parent-core ledger timing is not fabricated by invoking a
marker around IPC. The retained writer trace covers the whole run through the
final read, not an isolated sustained measurement window.

Raw store operation names and original request ids are stripped from retained
writer interval DATA. Public output contains bounded per-lane summaries.
The separate privateEvidence() capability retains sanitized intervals, actual
child stream facts/bytes and payer timing records for the future approved
manager; it is not a public JSON report or cleanup authority.

## Close remains the actual owned stop

The adapter reserves its close Promise before requesting the actual pair close.
It never delays that stop behind timing pagination: pagination belongs to the
tracked final read, so a drain deadline can request the pair stop immediately.

A clean close requires the real pair's returned-close outcome and both known
PAYER/SERVICE children: zero exit, no signal/fault/pending command, IPC
disconnect, ChildProcess close, actual stdout/stderr EOF, no overflow and
matching observed/retained byte counts. Missing acquisition, hidden activity,
failed/partial streams or uncertain close remain UNKNOWN. Every independent
lane still receives its stop; a late response cannot upgrade cached HELD.
