# Reservation-bound original funding observation

The durable issued-provider constructor now binds its actual reconciliation
callback through the same outcome-custody owner before creating the official
server. Legacy nondurable construction keeps its old callback. Binding itself
performs no port read/write, callback or SDK entry. This source candidate has
not executed the SDK, native journal, SQL or HTTP application.

The outer explicit resume still persists and reads back OBSERVATION_IN_FLIGHT
before calling the same continuation. The callback now independently reads the
exact current row, requires that phase and the next original observation count,
and compares the complete payload, requirement and issued challenge against
the original retained header/frame. The same custody owner claims this reserved
slot once before entering its captured frozen callback. Neither an SDK-shaped
retry nor a direct bridge settlement call can enter RPC/journal work from a
PENDING row or reuse a previously consumed reservation.

The callback's normalized result must retain the original hash, network and
payer. Only constructed primitive settlement DATA is resolved; returned
thenables, getters and serialization hooks are never assimilated. The same
current reservation is read again before a reply escapes. A changed row, lost
reservation ACK, rejected/opaque callback or closed owner keeps the original
reservation and HELD state. No receipt permits another first settlement or
refunds a reserved observation.

While the callback is active, new custody operations are refused. Closing fences
the owner and makes unknown in-flight work ineligible for backend retirement.
Late completion cannot read back, publish a result, overwrite custody or repair
HELD. The original callback Promise/opaque return remains retained where its
ownership is uncertain; no competing resource close or reopen is added. Stores,
SDK sessions and journal handles remain with their existing actual owners.

The SDK-free shared bridge, actual custody owner, actual pure original chain
observer and original journal projector can be composed with declared memory
ports. These checks demonstrate reservation-before-callback order, one first
attempt, weak-to-strong inclusion, bounded pending exhaustion and refusal of an
unreserved direct bridge call. Signature-shaped fixture fields remain
unauthenticated synthetic DATA. Parser checks on the real intake binding do
not execute it. Native persistence, current canonicality, cross-process fencing,
Linux, the 100 native calls/replay scenario and complete G0/G1/G2 remain OPEN.

Before wrapping, the intake uses the shared bridge's original callback-role
admission. Direct aliases among verifier, first settlement, observer and
challenge validator remain refused. The same admission function is reused by
the SDK-free bridge itself; it only captures descriptor-DATA and invokes no
callback. A trusted callback can still deliberately delegate to another
capability; these checks do not sandbox operational code.

Original role identities are checked again after intake issuance callbacks and
immediately before wrapping. Replacing a verifier/settlement method during
issuance cannot hide an observer alias behind the new wrapper.
