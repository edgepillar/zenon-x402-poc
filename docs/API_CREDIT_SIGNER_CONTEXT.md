# Full original context at the signer boundary

The fixed API-credit native application selects the context-required signer
file profile. Before real preparation, the native funding client binds its
already captured exact input to that same wallet owner. At the existing final
pre-sign handoff, the material planner binds the original plan and checkpoint
DATA before entering WalletAdapter.sign. No extra quote, read cycle, work,
nonce, key, signature or transport is produced by these two source bridges.

The live wallet admits each binding once. Its actual unsigned block must match
the handoff and original selected terms. One intent transaction then retains
the exact full preparation-input string, its reservation digest, resource URL,
original plan, unsigned checkpoint text and unsigned block. The SDK method
runs outside SQL. Its exact signed result is committed before candidate
acknowledgement, preserving the earlier loss/close/HELD policy.

The original budget schemas/token and generic legacy entries are unchanged.
The selected three-table profile uses `original_spending_signer_v2` with an
explicit 196608-byte record cap and the existing maxRecords/file/journal/space
bounds. Existing two-table or v1 signer files are refused, never migrated or
adopted. This is not permission to replace an existing account's ledger or
reset exposure. A migration needs its own reviewed preservation procedure.

The context codec checks exact DATA correspondence: the checkpoint's block
and quote match the original handoff, and the subject matches selected terms.
It is not a pre-sign checkpoint reader, current-price check, nonce/signature
verifier, authenticated chain observation or fresh authority. Signed history
is never passed to a pre-sign reader and cannot renew a quote or sign again.
Actual current-state validation/preflight remain separate downstream gates.

A pure, explicitly selected DATA projection requires the independent payment
id and original-input digest. A SIGNED record can deterministically encode the
same original x402 funding packet/checkpoint from the retained originals. It
does not change the block, re-quote, create a signature, open/write a store or
authorize commit/resend/service dispatch. INTENT alone cannot recover a missing
signature. The keyless operator consumer is still an OPEN source integration;
the existing funding-checkpoint inspector does not silently adopt this format.

Tests use fixed deliberately invalid signature-shaped bytes, declared methods
and memory stores. Native SDK/core/SQLite/HTTPS, actual process restart, signer
loss, cryptographic preflight, pricing/work and Linux remain unqualified.
Parser/DATA results do not establish the physical commit/release cutpoints.
